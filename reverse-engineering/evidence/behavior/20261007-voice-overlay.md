# 终端语音叠加控件证据

> 创建于 2026-10-07 · 最后更新 2026-10-07

## 原包依据

- 原包存在 `Ghostty.VoiceOverlay`、`VoiceOverlayModel`，并在 `TerminalSplitTreeView` 以 SwiftUI overlay 挂载。
- 模型字段为 `isVisible`、`pwd`、`timer`；符号显示按目录定时检查可见性。
- 原包字符串确认空闲按钮图标／帮助为 `speaker.wave.2.fill`、`clock.arrow.circlepath`、“朗读 Claude 最新回复（⌥⌘S）”和“打开朗读记录（看稿子、拖进度、回听历史）”。说明文本确认朗读中右上角替换为可暂停／继续、换倍速、看进度和停止的小播放器。

## 恢复实现

- `TerminalSplitTreeView` 的每个终端叶节点挂载 `VoiceOverlay`。
- 每两秒只读检查同一用户 Claude Code 进程的规范化工作目录；与该终端目录精确一致时显示，进程结束后隐藏。不读取环境变量、终端文本或会话正文。
- 空闲状态提供最新回复与朗读记录入口；准备／播放状态复用现有控制器和播放器，提供合成指示、暂停／继续、五档倍速、进度和停止。
- 进程快照补充所有已识别 Claude 进程的工作目录；已有会话编号、归属和不确定状态逻辑保留。

## 验证

- `check-voice-overlay-process.swift` 验证规范化目录精确匹配及非目标目录拒绝，实际通过。
- macOS arm64 Debug 完整构建通过；仅有项目既有 Swift 6／静态库符号告警。
- 使用本地最小等待程序作为无数据、无网络的合成 `claude` 进程：同目录启动后，最新构建的辅助功能树实际出现“小喇叭”和“朗读记录”两个按钮；停止进程后两按钮自动消失。
- 使用设置内固定示例和 macOS 系统语音完成实际播放态验证：小播放器显示暂停、1x、进度和停止；暂停后进度保持，切到 1.25 倍后控件更新，继续后进度推进，停止后恢复空闲入口。
- 在暂停态通过进度条的辅助功能“递增”动作把位置从约 12 秒调到约 15 秒，随后继续播放从新位置推进；这证明进度条绑定会提交定位，不只是改显示值。鼠标连续拖动和首尾边界仍归入 T-029 后续验证。
- 测试发现三处倍率格式会把 1.25 显示成 1.2，已统一改为保留实际有效数字；播放速度随后恢复为测试前的 1.0，录音保存保持关闭。
- 未读取真实会话、未保存录音、未发远程请求。测试进程已停止，临时目录已移入废纸篓，测试源文件已从工作区移除；修正后的最终 Debug 构建通过。
- 自动化关闭独立设置窗口时，绑定到该窗口的辅助功能调用会超时；进程采样显示主线程仍在正常 AppKit 事件循环，CPU 随后为 0%，未形成应用卡死证据。改用“窗口”菜单切回终端后完成了全部播放控件验证，因此不把工具绑定超时误记为产品通过或失败。

## 尚未通过

- 自动化只能确认系统音频管线进入播放状态，不能替代人工听感、语音内容准确性和不同输出设备测试。
- 原包尺寸、材质、间距、鼠标连续拖动边界和分屏多实例的视觉／交互对照尚未完成；本轮不声明像素一致或 UI-03／VOICE-04 整项验收。
