# 朗读开关桌面验证

创建于 2026-10-06 · 最后更新 2026-10-11

产物：`macos/build/Debug/Ghostty.app`。通过原生桌面接口操作实际窗口，未发送终端命令、未播放私人文本、未打开会话、未修改录音或提交远程请求。

## 实际结果

1. 编辑菜单显示朗读分组，停止朗读处于禁用状态；打开语音设置显示启用开关为 on，保存录音为 off，限额 50／300。
2. 关闭启用开关后，编辑菜单不再包含朗读分组。关闭设置窗口后，终端右键菜单也不再包含三项朗读操作。
3. 应用菜单仍包含语音朗读设置，通过该入口可以重新打开已关闭的设置窗口，启用开关保持 off。
4. 重新开启后，右键菜单恢复最新回复、选中内容、停止朗读三项；空闲停止仍禁用。测试结束恢复原有 on 状态，保存录音保持 off。

右键选择了终端登录提示中的普通单词，未执行朗读。没有检验合成中取消、播放中取消、跨窗口定向、键盘快捷键和重新启动后的配置读取，因此这些项仍未通过。应用菜单设置入口当前在末尾，原包关闭后的设置入口位置尚未取证，不把本记录当作像素或布局一致性证明。

## 叠加控件开关补齐

2026-10-11 原包静态字段确认 `VoiceSettings.showOverlay` 与 `VoiceSettingsModel._showOverlay`，原包界面文案为“在终端右上角显示小喇叭”，说明关掉后右键菜单和快捷键仍可朗读。恢复版新增同名中文开关，只在启用朗读时可操作；关闭后仅阻止 `VoiceOverlay` 显示，不改变朗读入口和播放能力。旧恢复版设置缺字段时默认保持显示，兼容此前行为。

原包同时存在 `autoPlay` 字段，但原包自身文案明确写着“Claude 一说完就自动念”还没做、下一期加，因此未把占位字段误恢复成原包并不存在的自动监听功能。原包设置窗口再次因辅助功能管道关闭而无法截图，未改动原包设置。

`check-voice-settings.swift` 验证旧 JSON 默认显示、关闭后的编码往返通过；`RecoveredWindowTests` 5 项和固定路径 arm64 Debug 构建通过。尚未在实际恢复版窗口点击开关，也未对照原包具体控件位置，因此 T-006／022 仅增加子步骤证据，不判整条通过。

## 系统中文音色补齐

2026-10-11 原包 `SystemSpeechSynthesizer.preferredChineseVoice()` 反汇编确认：先过滤语言前缀为 `zh` 的系统音色，再优先选择非默认质量，其次精确 `zh-CN`，最后使用第一项中文音色。原包设置模型同时存在 `voiceSelection`，界面字符串包含“当前系统音色”和“没找到中文音色”。

恢复版新增系统中文音色选择器，显示系统返回的名称和语言；选中标识继续写入原有 `voiceIdentifier`。实际系统合成的默认选声也改为复用同一优先级，避免设置显示与发声不一致。旧配置没有音色标识时按原包规则选择，不写入虚构默认值；已保存但系统已不存在的标识自动回退。

隔离检查确认本机目录只返回 `zh` 音色、首选项属于目录、音色标识编码往返；未播放声音。`RecoveredWindowTests` 5 项及固定路径 arm64 Debug 构建通过。原包选择器的准确位置、每个本机音色实际听感和重启后的桌面显示仍未验收，因此 VOICE-05／T-022 仍非整项通过。
