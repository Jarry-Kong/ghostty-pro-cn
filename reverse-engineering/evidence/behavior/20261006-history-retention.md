# 历史限额默认值与清理计划取证

创建于 2026-10-06 · 最后更新 2026-10-06

关联 VOICE-06、T-033。真实录音自动清理未启用，完整功能未验收。

## 原包证据

VoiceSettings.init 在 0x100154fa0—fc0 构造 voice.historyMaxCount 键与整数 50；0x100154fc4—fe4 构造 voice.historyMaxMB 键与整数 300，0x100155060 调用 registerDefaults。键所在 cstring 地址为 0x100944550 和 0x100944590，已核对原始字节。说明首次默认值为 50 次、300 MB，而不是从现有用户设置猜测。

enforceLimits 位于 0x100142084，0x10014218c 调用 recordingIDsOldestFirst；0x100142280 统计目录大小；0x100142544—56c 检查计数／容量是否超限；0x10014264c 调用 removeItemAtURL，原版为删除而非移入回收站。

后续精确字节换算已核实：VoiceSettingsModel.applyHistoryLimits 位于 0x10015c87c；0x10015ca6c 对无效值使用 300，0x10015ca70 执行 `lsl x0, x27, #20`，0x10015ca74 调用 maxTotalBytes.setter。因此容量为 MB 数值乘 1024×1024，默认 314572800 字节，不再是恢复版推测。

## 已实现与检查

新增纯清理目标计算及实际录音目录只读容量统计。仅在计数或容量超过上限时选最旧记录；检测重复编号、负容量、整数溢出和不安全路径。恢复版索引按新到旧保存，ISO 日期可能只有秒精度，同秒按索引后方旧记录优先，避免误选新录音。

独立检查通过等于上限保留、超限、50／51 条、计数和容量双条件、同秒顺序、重复编号及溢出。build-for-testing 退出码 0（同秒修正前版本），同秒修正后的独立检查通过；没有实际删除或移动数据。

## 决策与未完成

OPT-003：用户已明确选择“移入回收站，可找回”，批准这一原版差异。真实录音自动清理仍未启用；容量单位、设置界面和完整流程未验收。

后续已接入自动策略及条数／容量输入、应用确认、持久化与状态显示；新开启保存时告知限额和回收站行为，旧版已开启保存的用户需明确接受新的限额，不静默启用。取消后不重复询问，设置显示未开启。默认 50 次／300 MB；计数最小 1、容量最小 10 MB，非法整数及溢出拒绝。取消或清理失败不提交新设置。代理没有操作真实用户录音。

## 批准后的回收站实现与验证

新增回收站清理 API：按计划移出旧录音，再提交索引；索引失败则逐项从回收站恢复，不能恢复时报告仍可手动找回。每份录音增加 record.json 元数据快照，避免只找回 WAV 而丢失稿件和分段信息。索引写入用进程内互斥与非阻塞 lockf 跨进程锁，冲突报错不无限等待。

实际临时录音测试最初报 Cocoa 257，定位为 FileManager 枚举返回 /private/var，而解析路径为 /var 的别名比较错误。修正为标准化 URL 比较，并明确拒绝软链接；未请求额外系统权限。

真实合成样例已验证最旧录音移入回收站、元数据快照仍在、随后从回收站成功找回；索引目录只读时清理失败并恢复录音，索引字节保持不变；同进程重入写锁被拒绝。测试仅处理专用临时样例，找回后已清理，未留下测试录音到回收站，未清理用户真实数据。跨进程锁的真实双进程检查及界面策略接入仍待完成。

真实双进程检查已通过：独立子进程持锁，父进程冲突写入被拒绝且索引不变；子进程退出后可写。负例揭示未创建目录的软链接父节点校验不足，已补最近既有父节点校验；普通 macOS 路径别名不误拒，真实软链接父目录仍拒绝。检查脚本为 check-history-lock.swift。

新增明确刷新后的索引恢复：从回收站找回的完整目录经过快照与音频验证后重新入索引，重复刷新不重复导入，不会自动在启动时扫描迁移原版数据。临时录音“移入→找回→索引恢复→重复刷新”检查通过。完整设置 UI 与听觉／桌面流程仍未验收，不能将 API 检查替代整体 T-033 通过。
